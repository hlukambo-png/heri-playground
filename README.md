## 1. Briefly summarize your client, Artemis Financial, and its software requirements. Who was the client? What issue did the company want you to address?

Artemis Financial is a financial consulting company that develops individualized financial plans for customers, including savings, retirement, investments, and insurance. The company wanted to modernize its software application and improve its security to protect sensitive customer information. My responsibility was to identify potential software vulnerabilities and recommend security improvements. The primary goal was to ensure that the application could communicate securely, protect financial information, and reduce exposure to cybersecurity threats.

## 2. What did you do well when you found your client's software security vulnerabilities? Why is it important to code securely? What value does software security add to a company's overall well-being?

One area where I performed well was identifying security weaknesses through manual code inspection and static dependency analysis. I examined the application's source code, identified concerns involving hard-coded credentials, insufficient input validation, and outdated dependencies, and recommended appropriate mitigation strategies. I also used OWASP Dependency-Check to identify vulnerabilities in third-party libraries.

Secure coding is important because it prevents unauthorized access, protects confidential information, and reduces the likelihood of successful cyberattacks. Strong software security helps organizations maintain customer trust, protect their reputation, reduce financial losses, and support business continuity.

## 3. Which part of the vulnerability assessment was challenging or helpful to you?

The most challenging part of the vulnerability assessment was interpreting the results generated by OWASP Dependency-Check. The tool identified numerous vulnerabilities associated with outdated software dependencies, and I needed to understand their severity and potential impact.

This process helped me understand how vulnerabilities are classified and how developers can prioritize security improvements. I also learned that automated tools should be combined with manual code reviews because neither approach can identify every possible security weakness independently.

## 4. How did you increase layers of security? In the future, what would you use to assess vulnerabilities and decide which mitigation techniques to use?

I addressed defense in depth by identifying multiple areas requiring protection, including input validation, authentication, access control, secure communication, credential management, and dependency maintenance.

During the secure software project, I configured HTTPS using a development certificate and implemented SHA-256 hashing for data integrity verification. These measures demonstrated how encryption in transit and integrity checking serve different security purposes.

In future projects, I would use OWASP Dependency-Check, the OWASP Top 10, vulnerability databases, manual code inspections, and automated security testing. I would prioritize mitigation techniques according to vulnerability severity, exploitability, business impact, and available security updates.

## 5. How did you make certain the code and software application were functional and secure? After refactoring the code, how did you check to see whether you introduced new vulnerabilities?

I used application testing and security analysis to evaluate both functionality and security. During Project Two, I verified that the Spring Boot application started successfully, the HTTPS connection operated on port 8443, and the hashing endpoint displayed a successful integrity verification result.

I also generated an updated OWASP Dependency-Check report to evaluate vulnerable dependencies. The scan identified remaining security concerns, demonstrating that successful application execution does not automatically mean an application is completely secure.

In future development, I would perform regression testing, repeat dependency scans after modifications, review the updated code, and confirm that security controls continue functioning correctly.
